## A tenant that sets itself up, and a checklist that closes itself

Everything since v2.7.0. The through-line: the registry used to be something a
person had to fill in by hand before it could say anything. Now the system
produces the data the registry reasons about, and a new tenant can be walked
from empty to useful without a consultant in the room.

- [existing] **Setup wizard.** A guided first run that writes real configuration as you go
  (no staged blob that diverges from the tenant): pick a starter pack, choose
  modules against a live sidebar preview, route owners, then watch one real
  document satisfy several checklist items at once. Progress is resumable
  (migration 0101); abandoning it leaves a partially configured tenant, exactly
  what half an hour of manual admin would.
- [config] **Module visibility.** A tenant gates whole modules on or off and a department
  can be narrowed to what it uses. A disabled module is unreachable, not merely
  unlisted. Absence means unconstrained, so nobody's view changed on upgrade
  (0099).
- [config] **Approved documents close checklist items.** A document type now says what
  it normally satisfies (0100), so approving a COA suggests the requirement
  links a human used to tick by hand — as suggestions, never re-creating a link
  someone rejected. Supplier checklist rows record where they came from (0102).
- [existing] **Request composer + supplier portal.** Compose a document request against a
  supplier, issue it, amend it without destroying what was sent; the supplier
  answers through a no-login link, and what they upload is extracted and
  spec-checked on arrival but still accepted only by a person.
- [existing] **Renewals that route to an owner.** Annual by default, three years for spec
  sheets, never for a COA, decided and frozen at approval; a daily digest goes
  to each record's owner, and an unrouted record is reported, not re-broadcast.
- [existing] **Spec engine reads more of the page, and invents less.** Incubation-log
  timing rows no longer produce false passes; a lab's bare "Pass" is recorded
  as the lab's verdict, not laundered into ours; a unit is read from a column
  header or units row only when the page actually states it. Limits carry a
  criticality rank that orders what a reviewer sees without changing a verdict.
- [existing] **Register provenance + history backfill.** Every out-of-spec register row now
  says whether a reviewer judged it or a bulk pass did (0103), and
  `bin/backfill-spec-register` can fill the register for documents approved
  before it existed — dry run by default, nobody emailed, ever.

Still true: nothing files itself, and every one of these warns and asks a human.
