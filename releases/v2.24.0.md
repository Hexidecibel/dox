## One file is not one document

A supplier's annual packet arrives as a single 36-page PDF holding 25 separate
documents, each with its own type and its own expiry. dox read it as one
document: it came back classified as a letter of guarantee — page 3 answering
for all 25 — carrying a renewal date printed nowhere in the file, while an
audit certificate inside it lapsed months earlier. A packet like that is normal
practice, not a one-off.

The portal now notices before anything else happens, shows the page ranges it
found, and waits for a person. Nothing splits on its own: a wrong split turns
one wrong document into twenty-five.

### Added

- [existing] A supplier packet is no longer read as one document. When a PDF looks like several documents in one file, the review queue says so before anything else, shows the page ranges it found with a preview of each, and waits. A person splits it, adjusts the ranges, or says it is not a packet — nothing splits on its own.
- [existing] On the client's own 36-page supplier packet this finds all 25 documents exactly, and splitting it removes an expiry date the portal had invented from a clause on page 3.
- [existing] A single document is never offered a split: forty-four one-document files, including an eight-page plan with the same header on every page, are left alone.
- [config] A request line can now ask a supplier to send that document on its own, and the supplier sees it on their page.

### Changed

- _nothing_

### Fixed

- [existing] The link that opens the original file from the packet card no longer fails to load.

### Internal

- Two migrations, both additive: `0118_packet_split.sql` (nullable packet columns on `processing_queue` plus a partial index on the child side) and `0119_request_one_document_per_file.sql` (`request_lines.one_document_per_file`, mirrored onto template lines, NOT NULL DEFAULT 0). Every existing row reads exactly as it did the day before.
- Detection is pure (`shared/packetDetect.ts`) and runs on the per-page text and per-page image coverage the OCR pass already computed, so it costs no second read of the file. Signals in order of trust: the file's own index page, used verbatim — the layout signals move the confidence, never the ranges — then a repeated closing block, a title-shaped opening line against a closed list of document words, a picture page, a date line and a text-density jump. When the layout signals disagree the proposal goes coarse and says so rather than inventing precise-looking boundaries.
- Nothing auto-splits, and the schema can tell three states apart: nobody has looked, "not a packet" (remembered, so the card stops asking), and split into N. The parent becomes a container whose file stays the source of record; the approve path refuses it, because approving it would recreate the exact defect this exists for. Reject stays allowed and leaves the parts alone.
- Carving reuses the splitter the COA records path already runs (`extractRecordPdf`), and every range is carved before any row is written. Children inherit the supplier — the one fact a packet genuinely answers — and deliberately not the type.
- Measured with `bin/packet-detect`, no model calls: 26 of 26 page ranges exact on the real packet, the blank back cover reported as belonging to no part rather than bolted onto the last document, and zero false alarms across 44 single-document files. After splitting, 23 of 26 parts classify correctly with 95.5% of values read right and no fabrications.
- Only the index-page method has been measured on a real file. The letterhead path is unproven on any packet without a table of contents.
- Detection runs in the processing worker, so it reaches no document until that worker is restarted; it is not part of the Pages deploy.
