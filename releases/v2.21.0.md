## Sent documents, and why a limit was set

Everything that leaves the portal by email is now on a page you can read, and
anything on it can be pulled back. Alongside it: a supplier-specific spec limit
has to say why it exists, and two renewal rules stop guessing on your behalf.

### Added

- [existing] A "Sent documents" page lists every set of documents anyone has emailed out — recipients, how many times the link was opened, when it expires — and any of them can be revoked immediately; opens count requests against the link, not people, because the link can be forwarded.
- [existing] A supplier-specific spec limit asks why it was set and shows that reason next to the limit, and the reason is kept with every result it judged.
- [existing] Release notes now say whether a change reaches every organisation, only new ones, or needs configuring first.

### Changed

- [existing] Sending documents by email now requires more than read-only access.
- [new-orgs] New organisations now get the right renewal rule for each document type (a certificate of analysis does not renew; a specification sheet is three years).

### Fixed

- [existing] Renewal: a certificate we could not work out a due date for is no longer recorded as "does not renew" when a reviewer approves without answering.

### Internal

- Migration 0116 adds `document_export_links.revoked_by` — who pulled a sent link back. Nullable, no backfill.
- `defaultRenewalSettingForTypeName` (shared/renewalPeriod.ts) is now the single source for a document type's starting renewal policy, used by the API create path and both starter-pack appliers.
- `bin/fix-starter-pack-renewal-policy` corrects tenants seeded before that helper existed; it only touches rows still holding both migration defaults with no human decision on record.
