## On hold means it does not leave

A certificate can now be put on hold. A held certificate does not leave the
portal by any route until QA releases it.

### Added

- [existing] **Holds.** Anyone but a read-only account can put a lot's certificate, or a whole certificate, on hold with a reason. Only a QA person or an administrator can release it, with a written reason. Every hold and release is kept; nothing is edited or deleted.
- [existing] **A held certificate does not leave.** Not on an order, a resend, a ZIP, an emailed link, a link already sent, a bundle or an API key. Nobody releases a hold by sending. Opening or downloading the file while logged in is unchanged.
- [existing] **A lot hold follows the lot.** It covers every certificate from the same supplier that carries that lot: a second scan, a duplicate that was kept, a corrected certificate, and one that arrives later. It also stops any file that prints the held lot beside another. A different supplier's lot with the same number, and a different sublot, are not covered.
- [config] **A Critical result out of spec puts the lot on hold when the certificate is approved**, and QA is told. So does a sample-size mismatch on a zero-tolerance test. This needs a limit marked Critical, or a test whose category is zero tolerance. A method mismatch still only notifies, as before.
- [existing] **Holds page**, beside the Review Queue, with a count. If a hold should have been placed and could not be, the page and the certificate say so and offer a retry.
- [existing] Nothing existing was put on hold by this release, and nothing is sent to a warehouse system.

### Changed

- [existing] **The Critical tooltip no longer says holds are not enforced.**
- [existing] **A file that prints several lots takes the strictest sharing rule of any of them.** A locked lot no longer leaves on a neighbour's page.
- [existing] **A certificate reissued through "Replace existing" is checked against the new file**, so a held or locked lot on it is seen.
- [existing] **An order is marked delivered only when every line has actually gone** on a successful send.

### Fixed

- [existing] When one extraction was approved as several product certificates, its test results were not recorded and no warning was raised. They are now recorded against the right certificate, or against each when the page does not say which.
