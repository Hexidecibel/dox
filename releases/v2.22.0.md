## The page that is a picture

A supplier packet is rarely all typed text. Certificates get scanned, or pasted
in as a full-page image with nothing but a caption and a page number over them —
and those are exactly the pages that carry the expiry dates a renewal depends
on. Extraction used to decide about OCR for a whole document at once, so a page
like that was read as if it were nearly blank. It is now decided page by page.

### Added

- [existing] A certificate that arrives as a picture is now read. A page that is mostly an image with almost no text goes through OCR on its own, so certificate numbers, issuers and expiry dates on scanned or pasted-in certificates are extracted instead of coming back blank. On the client's own supplier packet this took the five certificate pages from nothing to 23 of 25 fields, including every expiry date a renewal depends on.
- [existing] A page of real text is never replaced by OCR, and only the pages that need it are read that way, so ordinary documents are unaffected.
- [existing] The review queue says which pages were read from an image, so a reviewer can see where a value came from.

### Changed

- _nothing_

### Fixed

- _nothing_

### Internal

- Migration 0117 adds `processing_queue.text_page_sources` — one JSON array, one row per page: the page number, whether its text came from the text layer, OCR, or both, how many characters each read produced, the largest drawn image as a fraction of the page, and the routing reason. Nullable, no backfill; the worker writes it only when at least one page was routed to OCR, so every existing row and every ordinary text document stays NULL and the review card is unchanged.
- Per-page routing lives in `shared/pdfPageOcr.ts` and is shared by the worker and the tests.
- `bin/eval-results-json` writes the evaluation corpus out document by document, so a run can be checked field by field instead of by its headline percentage.
- Measured after the merge: value accuracy 89.6%, image documents 23/25 graded fields, `document_expires_on` 5/5, doctype corpus 37/40 with per-page OCR confirmed not to fire there.
