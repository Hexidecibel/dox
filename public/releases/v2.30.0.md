## What may leave, and who says so

Every document now carries a sharing rule: send freely, needs QA approval, or
locked. The rule is held on every way a file can leave the portal, not only on
orders.

### Added

- [existing] **Every document has a sharing rule.** Send freely, needs QA approval, or locked. The document type sets it and one document can be given its own, with a written reason. The rule shows on the document page and on Document Types.
- [existing] **Starting rules, by type.** Send freely: certificates of analysis, specification sheets, allergen statements, kosher, halal and organic certificates, safety data sheets. Needs QA approval: audit certificates, HACCP and food safety plans, letters of guarantee, insurance. Locked: audit reports, W-9s. A type the portal does not recognise needs QA approval. Change any of them on Document Types.
- [existing] **A document with no type is locked** until an administrator gives it one. Opening or downloading a file while logged in is not "leaving" and is unchanged for every role.
- [config] **Who counts as QA.** A person on the "QA" owner route may release a document that needs QA approval; without a route it is the organisation's master user, then its administrators. Set the route under Owner routes.

### Changed

- [existing] **The rule is checked everywhere a file leaves:** a ZIP from search, an emailed link, the page a recipient opens, a bundle download, an order send and its resend, and any read by an API key. A locked document never leaves. One that needs QA approval leaves only when a QA person or an administrator sends it, and that is recorded as the approval.
- [existing] **Nothing is dropped quietly.** When a document is held back, the ZIP, the send, the bundle and the order each say which document and why.
- [existing] **Links already sent are re-checked each time they are opened.** A document locked after the link went out is no longer served. One that now needs QA approval is served only if the person who sent the link may release it.
- [existing] **An API key reads send-freely documents only**, and can never loosen a rule, whoever owns the key.
- [existing] **Only an administrator can move a document off locked**, whether by setting its own rule or by changing its type. Changing a document's type so that its rule loosens needs the same authority as changing the rule.

### Fixed

- [existing] A bundle download no longer includes a deleted document, names any file it could not include, and is now written to the audit log.
- [existing] A document could be given a type belonging to another organisation. It is refused.
